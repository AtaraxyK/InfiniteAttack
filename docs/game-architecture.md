# Game Architecture

## 목표 루프

이 게임의 핵심 루프는 아래처럼 단순하게 유지하는 것이 좋습니다.

1. 방치형 건물과 오프라인 진행으로 재화를 확보
2. 영웅 레벨, 장비, 건물 보너스로 전투 점수 강화
3. 스테이지에서 장비 조합을 선택하고 결과 계산
4. 보상으로 다시 성장 루프에 복귀

즉, 조작의 재미보다 `선택과 성장의 누적`이 중심입니다.

## GitHub Pages 제약과 해석

GitHub Pages는 정적 호스팅이므로 다음 기준으로 설계합니다.

- 게임 코어 로직은 모두 클라이언트에서 동작
- 계정 저장은 외부 서비스에 위임
- 서버 검증이 꼭 필요한 경쟁형 시스템은 뒤로 미룸

현재 구상에는 이 방식이 잘 맞습니다.

## 시스템 단위 설계

### 영웅

- 레벨
- 기본 스탯: 공격력, 방어력, 체력
- 성장 테이블
- 장비 슬롯
- 건물/연구/패시브 보너스 합산

권장 구현:

- 내부 계산값은 `bigint`
- UI 출력은 별도 포맷터 사용

### 장비

- 무기
- 보조 장비
- 강화 단계
- 시너지 태그

전투에서는 발라트로처럼 복잡한 카드 규칙을 그대로 가져오기보다:

- 무기 1장
- 보조 1장
- 특정 조합 보너스

이 정도로 시작하는 것이 구현과 밸런싱 모두 안정적입니다.

### 전투

전투는 실시간이 아니라 `선택 후 계산` 구조로 설계합니다.

기본 흐름:

1. 스테이지 진입
2. 장비 또는 패 선택
3. 공격 점수 계산
4. 적 요구치 또는 적 행동표와 비교
5. 결과 로그 생성
6. 보상 지급

초기 버전은 다음 공식을 추천합니다.

```ts
combatPower =
  heroAttack
  + selectedWeaponPower
  + selectedAuxPower
  + buildingBonus
  + synergyBonus
```

이후 확장:

- 치명타 기대값
- 속성 저항
- 라운드별 보정
- 적 패턴

### 건설

요구사항에 맞춰 구조를 아래처럼 유지하면 됩니다.

- 건설 라인 2개
- 각 라인별 예약 1개
- 완료 즉시 적용 금지
- 사용자가 `완료 확인`해야 효과 반영

이 구조는 방치형 게임에서 "돌아와서 확인하는 맛"을 만들어줍니다.

건설 데이터 모델 예시:

```ts
type ConstructionLane = {
  laneId: number;
  activeProject: ActiveConstruction | null;
  queue: QueuedConstruction | null;
};
```

### 재화

재화는 3종 정도로 시작하는 것이 적당합니다.

- 골드: 일반 소비
- 스크랩: 건설/강화 재료
- 에테르: 희귀 성장 재화

권장 규칙:

- 일반 재화는 자주 순환
- 희귀 재화는 해금과 장기 성장 축 담당

### 오프라인 진행

방치형 완성도는 여기서 갈립니다.

필수 항목:

- 마지막 저장 시각
- 건설 종료 시각
- 재화 생산량
- 최대 오프라인 누적 시간

재접속 시 처리:

1. 경과 시간 계산
2. 누적 생산 반영
3. 완료된 건설 표시
4. 수동 확인 대기 상태 전환

## 저장 구조

### 로컬 저장

초기 버전은 로컬 저장부터 완성하세요.

- `localStorage`: 빠르게 시작하기 좋음
- `IndexedDB`: 데이터가 커지면 이전

`bigint`는 JSON 직렬화가 안 되므로 문자열로 저장해야 합니다.

### 클라우드 저장

GitHub Pages에서 클라우드 저장을 붙이려면 외부 서비스가 필요합니다.

추천:

- `Supabase Auth`
- `Supabase Postgres`

초기 전략:

- 비로그인 상태는 로컬 저장
- 로그인 시 클라우드 세이브 사용
- 필요 시 로컬과 충돌 해결 정책 추가

## 상태 관리 추천

프로젝트가 커지면 아래 구성이 편합니다.

- 순수 함수: 전투 계산, 오프라인 계산
- 전역 상태: 영웅, 재화, 건설, 장비
- 영속화 계층: save/load

나중에 확장할 때는 `Zustand`를 붙이기 좋고, 현재 초안은 React state만으로도 충분합니다.

## 구현 순서

1. 저장과 로드
2. 오프라인 진행 계산
3. 건설 효과 테이블화
4. 장비 인벤토리와 강화
5. 스테이지 해금
6. 클라우드 저장
7. 연출과 밸런싱

## 주의할 점

- 브라우저 시간을 그대로 믿으면 치트가 가능함
- 경쟁 요소가 없다면 초반엔 크게 문제되지 않음
- 큰 수치는 반드시 처음부터 포맷 규칙을 정해야 함
- 수동 완료 확인은 UX가 번거롭지 않게 명확한 알림이 필요함
